## Purpose

This matrix defines the denominator for Universal Coding Memory evidence. It is
an inventory and proposed contract, not an accepted ADR or architecture
baseline. A PoC is blocked when its applicable interfaces are absent from this
matrix or the generated inventory.

DEC-11 accepts the local macOS development and evidence route. DEC-13 selects
project-specific processing-policy Option A (`zero-egress` by default;
`provider-enabled` only under an exact accepted provider manifest). DEC-14
selects bearer-authenticated viewer Option A, with `GET /agentmemory/livez` as
the sole unauthenticated route. The
[human disposition](../reports/iteration-4-local-macos-human-disposition-2026-07-28.md)
does not baseline this Draft matrix, close a veto, or authorize implementation.

The deterministic source inventory is
`.aiwg/reports/g-icm-01-interface-inventory.json`, generated by
`npm run evidence:interfaces`. The current candidate tree contains:

- 135 REST routes: one explicitly public liveness route and 134 protected
  routes;
- six MCP HTTP routes, 59 tools, five resources, three prompts, and seven
  reduced standalone fallback tools;
- 13 packaged lifecycle hooks and 44 declared events across five host
  manifests;
- 18 host connector adapters;
- viewer server paths, generic REST proxy status, and literal UI REST
  expressions; and
- all provider adapter classes discovered under `src/providers`.

The starting revision's 115 missing-auth routes are retained in the R-14
pre-fix receipt. The current inventory reaches zero missing protected routes,
but that is remediation evidence only and does not retire R-14.

The generated inventory also declares a fail-fast risk-backlink denominator:
22 interface-applicable risks, 22 represented, and zero missing. R-12 is
explicitly excluded because distribution governance has no product runtime
interface. Cross-cutting classifiers attach R-10 and R-18 through R-23 to
project/scope, MCP, native-sync, lifecycle, capture/dedupe, compaction, and
worker/health surfaces without changing their primary control classification.
This repairs evidence coverage only; it does not accept the matrix or any risk.

## Cross-Surface Rules

1. `GET /agentmemory/livez` is the complete public-route allowlist. Detailed
   health is authenticated because it exposes dependency and runtime telemetry.
   Every other REST route requires authenticated middleware. Under
   `deployment_target=local-macos`, the static viewer shell, viewer assets, and
   viewer-data routes require bearer authentication; there is no public-shell
   exception.
2. A missing or unreadable server secret makes protected REST and MCP surfaces
   unavailable. It never disables authentication.
   A proxy authentication, authorization, project-binding, required-backend,
   or protected-operation failure never downgrades to unauthenticated local
   execution. Any accepted offline mode is explicit, separately scoped, and
   visibly degraded.
3. Project-bound operations require canonical `project`. Global access requires
   an explicit `scope=global` input and an audit event.
   The scope-less `agentmemory://graph/stats` resource is intentionally absent;
   graph reads use the scoped MCP tool or REST route.
4. Capture admission, authoritative policy resolution, exclusion, and
   redaction precede serialization, transport, fingerprint/dedupe material,
   logging, queue/retry state, persistence, indexing, and every provider,
   native-memory, export, snapshot, backup, viewer, or other governed sink.
   Missing policy fails closed; lower-precedence configuration, implicit
   session creation, and provider fallback cannot relax it.
5. Context reports each required and optional source outcome. Required-source
   failure is `failed`; allowed optional-source failure is `degraded`.
6. Packet generation, dispatch, acknowledgement, and consumption are distinct
   states. Only a valid acknowledgement suppresses a source for a session.
7. Migration and restore use complete state manifests. A failed operation
   leaves either the pre-operation generation or the target generation.
8. Health distinguishes process liveness, required-backend readiness, pressure,
   compatibility, worker capture readiness, reconciliation, and recovery
   windows. Responsive engine/viewer ports do not substitute for a required
   connected worker.
9. Recalled content is advisory. Tests, runtime receipts, commits, live source,
   and accepted external ADRs remain authoritative.
10. Viewer values and destructive actions expose project/global scope, named
    denominator, snapshot identity/time, and authorization. A project view
    never silently renders global or another project's durable memory.
11. Native-memory synchronization requires an explicit user action, exact
    project/source/destination binding, and atomic destination preservation.
    Automatic hooks and global/unscoped source selection are denied.
12. `deployment_target=local-macos` is orthogonal to C1/C2/C3 and to processing
    policy. Project-specific `zero-egress` is the default; `provider-enabled`
    requires an exact accepted provider manifest. Local placement alone
    authorizes no external attempt.
13. Each instance LaunchAgent owns one supervisor; the supervisor owns one
    managed iii generation, one worker/server generation, and any selected
    local gateway/relay generation. Startup, readiness, capture readiness,
    drain, reverse shutdown, and bootout follow ADR-007. Unowned processes are
    never signalled.
14. Runtime-release generation and data generation have distinct immutable
    identities and pointers. Upgrade and rollback use one coordination
    transaction and expose only a qualified prior or target compatibility pair.
15. Normal, canary, and rollback instances share no mutable path, credential,
    port, lock, queue, registry, or generation pointer. C2/C3 gateways and the
    C3 relay remain same-host and loopback-only; off-host operation is deferred.

This reversible operator control was accepted, applied, and qualified for one

## Denominator Rules

- REST denominator: every generated route plus the static viewer shell, every
  viewer asset/data bootstrap path, stream path, redirect, and generic proxy
  resolution. The generator fails `--check` when any route other than exact
  `GET /agentmemory/livez` lacks the accepted authentication control.
- MCP denominator: all tools returned by `getAllTools()`, including whether
  `project` and `scope` are declared and required, plus transport routes,
  resources, prompts, standalone fallback tools, every proxy error class, and
  every local read/write/persistence side effect.
- Hook denominator: every `hookEntries` member in `tsdown.config.ts`, in both
  `dist/hooks` and `plugin/scripts`, plus every declared host-manifest event.
- Provider denominator: every discovered provider adapter plus each query,
  embedding, vision, migration, fallback, telemetry, mesh, relay, and outbound
  transport attempt site, evaluated once under `zero-egress` and once under
  the exact `provider-enabled` policy.
- Capture-state denominator: every immutable event/attempt identity and every
  observation, ledger, history, search/vector index, count, stream, audit,
  outbox, and active-generation effect required for its terminal result.
- Generation denominator: every immutable runtime release, data generation,
  schema/configuration/identity generation, compatibility pair, prior/target
  pointer, coordination transaction, process-death boundary, reconciliation
  outcome, audit record, retention action, and rollback/readback result.
- Native-sync denominator: every explicit action, named immutable source ID,
  authorized project, destination pre/target image, attempt, audit/outbox
  effect, and automatic path that must produce zero writes.
- Traceability denominator: every generated surface carries at least one
  control, requirement, risk, and executable test backlink.
- Risk-backlink denominator: every interface-applicable risk declared by the
  generator is represented at least once; generation fails on any omission.
  An excluded risk requires an explicit reason in the generated artifact.
- Revision denominator: the inventory records the source commit, committed tree,
  and a SHA-256 digest of every file parsed to generate the denominator.
- Connector denominator: all `ADAPTERS` entries and integration manifests.
- Viewer denominator: shell/assets/data authentication, explicit server paths,
  generic proxy contract, every statically discoverable literal UI REST
  expression, project-health and slot equivalence, every rendered value or
  destructive action, its project/global scope and authorization, snapshot
  ID/time and named denominator, and the bounded unavailable/degraded/
  recovering/healthy transition history behind the current render.
- Diagnostic denominator: every Doctor/diagnose check and capability, its
  pass/warning/fail outcome, affected record/interface denominator, project or
  global scope, observation time, evidence source, and next action. Aggregate
  healthy cannot omit or downgrade a warning or failed subordinate capability,
  and diagnostics authorize no repair or migration.
- Local lifecycle denominator: immutable package/release/current-pointer
  resources; setup/status/doctor/upgrade/rollback/uninstall operations; every
  normal/canary/rollback LaunchAgent, supervisor, iii, worker, port, secret,
  policy, project registry, runtime/data pointer, queue, pidfile, lock, log,
  backup, connector, gateway, and relay resource; ordered startup/drain/
  shutdown; both processing modes; every failure and exact cleanup/readback.
- Test denominator: all 148 governed `*.test.ts` files. Omitted or skipped
  mandatory authentication/integration evidence fails the receipt.

## Review Boundary

Configuration Manager signs inventory completeness. Software and Security
Architects review proposed contracts. Test Architect reviews the verification
denominator. Their review does not accept ADRs, baseline architecture, change a
risk status, authorize Construction, or authorize rollout.
