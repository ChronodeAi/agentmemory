# Bounded PoC Plan

Status: Planned only - no PoC executed

Scope: ABM risk evidence only

## Guardrails

- Use isolated temporary homes, synthetic repositories, synthetic secrets,
  disposable iii-engine state, and recording provider sinks.
- Do not use production memory, production credentials, live user content,
  deployed provider directories, or the Memetics canary.
- Pin each run to the source SHA and fixture-manifest SHA.
- Stop on the first cross-project disclosure, raw secret occurrence,
  unauthenticated protected response, prohibited egress, mixed migration
  generation, unbounded resource growth, or corrupted rollback.
- A passing PoC creates evidence for later owner and gate review only. It does
  not change a risk status, accept an ADR, baseline architecture, or authorize
  Construction, distribution, rollout, or production use.

## Common Receipt

Every run must capture:

- risk ID, card version, source SHA, fixture SHA, artifact SHA;
- argv as a structured array, start/end time, duration, exit code, and signal;
- OS, architecture, CPU, RAM, Node, npm, Vitest, iii-engine, and Agentmemory
  versions;
- worker count, ports, non-secret feature flags, process-tree peak RSS, and
  disk/log growth;
- test IDs, tracked-file denominator, skipped-test list, and raw result hashes;
- input/output counts, project IDs, provider attempts, and typed failure states;
- synthetic-secret scan results without recording any real credential value;
- execution operator identity and immutable raw-receipt signer.

Before any card starts, `G-ICM-01` must enumerate the relevant REST, MCP, hook,
viewer, provider, authentication, project-scope, and failure-state surfaces.
If the matrix cannot identify the complete surface denominator, the card is
blocked rather than partially passed.

After a run receipt is sealed, the accountable owner and every named independent
reviewer must record a separate disposition against that immutable receipt.
Those post-run dispositions are review evidence and do not alter risk status
without a later authorized gate cycle.

## R-07 - Bounded Capture and Observability

- Owner: Performance Test Owner.
- Reviewers: Service Owner, Test Architect, Operations Owner.
- Timebox: 2 days.
- Dependencies: R-13 harness, declared host/concurrency profile.
- Hypothesis: four-agent capture and context traffic remains bounded while the
  generated runtime keeps sampling at or below 0.1 and console logging off.
- Pass evidence: p95 below 2 seconds by hook class, p99 below 5 seconds, no
  forced hook timeout, maximum capture queue depth at or below 256 events, zero
  dropped events, zero recursive trace IDs, peak process-tree RSS at or below

- Fail evidence: threshold breach, absent queue/drop telemetry, event loss,
  deadlock, recursive log amplification, or resource growth beyond either fixed
  ceiling.
- Containment/backtrack: stop load immediately, cap concurrency, disable
  nonessential capture, restore the known bounded telemetry profile, and
  preserve only redacted receipts.
